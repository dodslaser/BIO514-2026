3.2 BLAST

The sequence you looked at above is from the gene ACT1, which is quite conserved in eukaryotes and encodes actin. This sequence was collected from the Saccharomyces Genome Database (SGD) and is an S. cerevisiae reference sequence. But let’s say that we want to look at this gene/protein in other organisms too.

The ACT1 sequence of another species has already been saved for you in the directory for this course (collected from NCBI, which you will work with later). To get to this directory, use the following path: /cephyr/NOBACKUP/groups/n2bin_gu/ from here, navigate to the BIO514 introduction folder. Copy the file more_actin.fa to your own workspace.

To find out what species this sequence originates from, we can use BLAST (Basic Local Alignment Search Tool). This is a widely used program to compare nucleotide or protein sequences to a database of known sequences. By identifying regions of local similarity, homology, functional predictions of unknown sequences and of most likely organisms of origin can be determined. To use BLAST, we can see if it is already loaded by default in our environment. If this is not the case, check its availability on the server & load it into your own environment. Check that this has worked correctly.

Tip

Environment modules can be accessed using the module command.

Think about which flags you will have to use, and where you wish to store the output. Look at your results. What species are you working with? Store this information in the header of the file.

3.4 CLUSTAL

Now that all your DNA sequences are in one file, you can use the multiple sequence aligner CLUSTAL to visualize which parts are the most conserved. There are different programs in the Clustal family (e.g. ClustalW and Clustal Omega, both available online too), using different algorithms but serving the same purpose.

Clustalo is not by default loaded in your environment and is also not among the available modules on the server. A third way to work with a tool on the cluster is using a container. A container is a packaged software environment that contains a program and everything it needs to run. Using containers helps avoid problems with missing dependencies and makes analyses more reproducible as well. A container has already been built for you and can be found under ‘images’ in the BIO514 folder.   ::: {.callout-tip} For this course we will use apptainer/singularity containers. :::

3.5 Submitting jobs to compute nodes

So far, you’ve been working in your login node. This is a shared entry point used my many users at the same time. This has been perfectly fine, as it is intended for light, low-resource, interactive tasks. Running CLUSTAL will be a bigger job though. For jobs such as these, it is good practise to instead book compute cores. You request dedicated computing resources for your job. While your job is running, those cores are reserved for you, and you are free to run more demanding analyses without affecting other users.

To run jobs in this way, you should submit them to the scheduler, here SLURM. C3se provides a manual to do this. Write a simple job script. Start with the shebang, followed by the project account information (not sure? Try running projinfo in the terminal). Specify the right partition. One CPU core, 10 minutes, will be enough. Then write your command to execute the clustalo script you have just created.

Before submitting your job, check to make sure both scripts have the right permissions. Then it is time to submit your job! Don’t forget you can check on its status too.

3.6 Sequencing data

Aside from fasta, another very common bioinformatic filetype is fastq, containing quality information as well as sequence information. On the Canvas page for this course, under ‘labs’, ‘introduction’, you can find paired-end Illumina sequencing reads in fastq format.

Upload these files to your working directory. Unzip the files and check their contents. Does the format make sense to you?

Raw sequencing reads often contain low-quality bases, adapter sequences, or other technical artefacts that can interfere with downstream analyses. For this reason, reads are commonly pre-processed before mapping or assembly.

fastp is an all-in-one tool that performs both quality control and filtering/trimming of sequencing reads in a single step. It is not available on the cluster, but you can build a container yourself!

We will do this using apptainer. Start by installing Apptainer on your Linux system (or WSL on Windows):

sudo apt install apptainer

If this works, skip the rest of this section and move on to creating your definition file. If not, your system does not provide Apptainer through the package manager. In that case, it can be built from source:

git clone https://github.com/apptainer/apptainer.git
cd apptainer
git checkout v1.3.1
./mconfig
make -C builddir
sudo make -C builddir install

Apptainer is written in Go, so if you do not have this yet, you might need to install it first:

wget https://go.dev/dl/go1.22.0.linux-amd64.tar.gz
sudo tar -C /usr/local -xzf go1.22.0.linux-amd64.tar.gz
echo 'export PATH=/usr/local/go/bin:$PATH' >> ~/.bashrc
source ~/.bashrc
You might also need uidmap if it is not yet installed:
sudo apt install uidmap

Next, create a definition file to build your container. This file describes which base system to start from, what software to install and how the container should behave when run.

  1. Create a file which you can call fastp.def with the following contents:

    Bootstrap: docker
From: mambaorg/micromamba:1.5.8

%post
   micromamba install -y -n base \
      -c conda-forge \
      -c bioconda \
      fastp && \
   micromamba clean --all --yes

%environment
   export PATH=/opt/conda/bin:$PATH

%runscript
   exec fastp "$@"

  2. Build the container

    apptainer build fastp.sif fastp.def

  3. Once your container is built, copy it to the HPC! :::{.callout-tip} When the container is executed, it behaves as if you are running fastp. So any arguments you pass to the container are forwarded to fastp – similarly to how you ran clustalo previously. :::

  4. Run fastp on your samples. The default settings are fine, but feel free to make changes. How to run this tool is well described in this BIO511 tutorial. How much of your data was filtered out?

4 Mapping to a reference genome

For most analyses, your individual sequencing reads will have to be mapped/aligned to a reference genome next. A lot of different mapping tools exist. One of these, already available on the cluster, is called BWA (Burrows-Wheeler Aligner). Consisting of different algorithms, the one most suitable for your samples is called BWA-MEM.

Before running this tool, a reference genome is necessary. As the name of your samples implies, you will need a mouse reference. You can get this from ENSEMBL, another large resource providing various genomes and tools, using the following command:

wget https://ftp.ensembl.org/pub/release-113/fasta/mus_musculus/dna/Mus_musculus.GRCm39.dna.primary_assembly.fa.gz

4.1 Indexing

Many tools require indexing of large files like this one. In this case, it allows the aligner to more efficiently and quickly find where a read could map to our reference. Creating an index only has to be done once for any given file. Make sure not to run this task on your login node as it is more demanding.

4.2 Mapping

Once you have created your index, it is time to try running BWA-MEM. The output of this tool is a .sam file though, which is plain-text and human-readable, but very large and inefficient to store/process. Usually these are not stored directly, but instead immediately converted to a .bam file, containing the same information in binary format – smaller and faster to read and write. We can use SAMtools, also available on the cluster as a module, to do this. Pipe the output of bwa mem directly into samtools view, to convert it to a .bam file, and then pipe this to samtools again, to sort the file, which would be required by most downstream tools, allowing easier access to specific genomic regions.

4.3 Interpretation

Now we can check the success of our alignment using flagstat, and stats, both also a part of samtools. We can use samtools view to take a look at the header of the SAM file as well. In the top of the file, all lines start with ‘@’. This is part of the header. The second part contains detailed information about your mapping. Do you understand the different columns?

There are many other tools available to perform mapping. Find a second tool, either available on the cluster or from elsewhere, and compare the results.
